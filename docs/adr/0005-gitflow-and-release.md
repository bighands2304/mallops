# 0005 — GitFlow branching and automated releases

- Status: Accepted · 2026-11-20

## Context
The project needs a clear contribution flow, stable releases, and a way to ship pre-releases for testing.

## Decision
- `main`: only released code; every commit is a tag `vX.Y.Z`.
- `dev`: default branch, integration of `feature/*` and `fix/*` via PR.
- `release/X.Y.Z`: cut from `dev` by the *Start release* workflow; every push publishes a GitHub pre-release `vX.Y.Z-beta.N`. It acts as the beta channel, so no extra long-lived `beta` branch.
- `hotfix/*`: from `main`, merged back to `main` and `dev`.
- Conventional Commits enforced on PR titles (squash merge); changelog generated by git-cliff.
- Merge of a release/hotfix PR into `main` tags, creates the GitHub Release with binaries, publishes crates, and opens a back-merge PR into `dev`.

## Consequences
- One click to start a release, zero manual tagging.
- Squash merges keep history linear and changelog accurate.
